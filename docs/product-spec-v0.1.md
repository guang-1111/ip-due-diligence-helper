# 知识产权网络核查助手 MVP 产品规格书 v0.1

## 1. 产品定位

知识产权网络核查助手是一个面向律师、实习生和尽调团队的本地半自动化工具。它的目标不是绕过网站限制或替代人工判断，而是把知识产权网核中重复、机械、容易漏项的工作标准化：

- 按权利人名称在指定公开网站查询；
- 保存查询结果目录页；
- 逐项进入知识产权详情页并保存；
- 按项目要求自动分类、命名和归档；
- 记录查询日志；
- 生成截图完整性核对报告。

第一版 MVP 采用“统一框架 + 商标模块可运行 + 其他模块预留”的策略。

## 2. 用户场景

典型使用者拿到一个项目的主体清单，主体可能包括发行人、集团公司、子公司、孙公司、分公司或其他关联企业。使用者需要以这些主体作为权利人，在多个公开网站查询知识产权或备案信息，并保存底稿 PDF。

典型工作要求包括：

- 所有查询过程需要截图或打印为 PDF；
- 目录页和详情页均需保存；
- PDF 需要显示核查日期、网页地址、页码等基本信息；
- 文件夹需要按项目组要求分类；
- 文件名需要满足项目底稿习惯；
- 查询完成后需要检查是否遗漏截图。

## 3. MVP 范围

第一版必须实现：

- 新建网核项目；
- 支持 Excel 导入权利人清单；
- 支持直接粘贴权利人清单；
- 对权利人名称做快速格式检查；
- 支持用户选择目录结构；
- 支持用户选择或自定义文件命名规则；
- 显示五类网核模块；
- 商标模块可自动执行；
- 专利、著作权、ICP/域名备案、工信部进网/认证模块预留；
- 连接已登录的可见浏览器；
- 按权利人名称进行商标查询；
- 保存商标目录页 PDF；
- 尝试逐项保存商标详情页 PDF；
- 遇到验证码、登录失效、页面异常时暂停并提示人工处理；
- 生成运行日志；
- 生成核对报告。

第一版不实现：

- 强联网企业真实性校验；
- 绕过验证码；
- 自动注册或自动登录；
- 专利、著作权、ICP/域名备案、工信部进网/认证的完整自动抓取；
- 云端部署；
- 多人协作；
- 自动修改律师工作报告或附件；
- 无人工监督的长时间后台爬取。

## 4. 总体流程

```text
新建项目
→ 导入权利人清单
→ 主体名称快速检查
→ 设置目录结构
→ 设置文件命名规则
→ 选择网核模块
→ 登录/连接浏览器
→ 执行商标网核
→ 保存目录页和详情页
→ 处理异常和人工暂停
→ 生成日志
→ 生成核对报告
→ 输出项目文件夹
```

## 5. 项目初始化

## 7. 主体名称快速检查

第一版不做强联网校验，不使用百度搜索作为主体真实性依据。系统只做快速格式提醒，避免拖慢流程和引入误判。

### 7.1 检查规则

| 检查项 | 状态 | 处理方式 |
|---|---|---|
| 空值 | 错误 | 标红，必须删除或补充 |
| 重复名称 | 提醒 | 标黄，允许继续 |
| 名称过短 | 提醒 | 少于 4 个汉字或 6 个字符时标黄 |
| 未识别完整组织后缀 | 提醒 | 标黄，提示可能是简称 |
| 文件名非法字符 | 自动处理 | 保存时替换为安全字符 |
| 前后空格 | 自动处理 | 自动 trim |

### 7.2 完整组织后缀白名单

系统识别下列后缀：

- 有限公司；
- 有限责任公司；
- 股份有限公司；
- 集团有限公司；
- 集团股份有限公司；
- 分公司；
- 合伙企业；
- 普通合伙企业；
- 有限合伙企业；
- 特殊普通合伙；
- 个人独资企业；
- 外资企业；
- 全民所有制；
- 集体所有制；
- 联营企业；
- 股份合作企业；
- 律师事务所；
- 农民专业合作社；
- 农民专业合作社联合社。

## 8. 目录结构配置

目录结构必须由用户选择或自定义，不写死。

### 8.1 内置模板

模板 A：按权利类型优先

```text
{项目名}/{权利类型}/{权利人}/{文件名}
```

示例：

```text
示例项目/商标/示例科技（北京）有限公司/10000000_详情页.pdf
```

模板 B：按权利人优先

```text
{项目名}/{权利人}/{权利类型}/{文件名}
```

示例：

```text
示例项目/示例科技（北京）有限公司/商标/10000000_详情页.pdf
```

模板 C：按底稿习惯

```text
{项目名}/{权利类型}-{主体层级}/{权利人}/{文件名}
```

示例：

```text
示例项目/商标-子公司/示例科技（北京）有限公司/10000000_详情页.pdf
```

### 8.2 自定义变量

用户可以使用下列变量：

| 变量 | 含义 |
|---|---|
| `{项目名}` | 项目名称 |
| `{权利类型}` | 商标、专利、著作权、域名备案、工信部进网认证 |
| `{主体层级}` | 发行人、子公司等 |
| `{权利人}` | 权利人名称 |
| `{权利号}` | 注册号、专利号、登记号等 |
| `{分类号}` | 商标分类号等 |
| `{页类型}` | 目录页、详情页 |
| `{日期}` | 核查日期 |
| `{序号}` | 当前主体或当前权利项序号 |

### 8.3 路径预览

用户每次调整目录结构或命名规则时，系统应立即显示预览：

| 类型 | 示例路径 |
|---|---|
| 目录页 | `示例项目/商标/示例科技（北京）有限公司/示例科技（北京）有限公司_商标目录页.pdf` |
| 详情页 | `示例项目/商标/示例科技（北京）有限公司/10000000_详情页.pdf` |
| 多分类详情页 | `示例项目/商标/示例科技（北京）有限公司/10000000（44）_详情页.pdf` |

## 9. 文件命名规则

### 9.1 默认规则

目录页默认：

```text
{权利人}_{权利类型}目录页.pdf
```

详情页默认：

```text
{权利号}_详情页.pdf
```

同一权利号对应多个分类号时：

```text
{权利号}（{分类号}）_详情页.pdf
```

无结果目录页：

```text
{权利人}_{权利类型}无结果页.pdf
```

异常页面：

```text
{权利人}_{权利类型}_异常_{时间戳}.pdf
```

### 9.2 文件名冲突规则

如果目标文件已存在，用户可配置：

| 策略 | 说明 |
|---|---|
| 跳过 | 默认策略，不覆盖既有文件 |
| 覆盖 | 覆盖既有文件 |
| 自动追加序号 | 例如 `_2`、`_3` |

第一版默认使用“跳过”，避免误覆盖底稿。

### 9.3 安全字符处理

Windows 文件名非法字符需替换：

```text
< > : " / \ | ? *
```

替换为：

```text
_
```

原始权利人名称仍需保留在日志和报告中。

## 11. 浏览器接管逻辑

### 11.1 设计原则

工具应模拟真实人工操作，不设计强反爬能力，不绕过验证码，不隐藏浏览器。

第一版推荐模式：

```text
用户手动打开浏览器并登录
→ 用户停留在目标查询页面
→ 工具连接已有浏览器
→ 工具接管页面执行重复操作
```

### 11.2 浏览器模式

| 模式 | 第一版状态 | 说明 |
|---|---|---|
| 连接已有浏览器 | 必须支持 | 用户先登录，工具连接 |
| 自动打开浏览器 | 可选 | 工具启动可见浏览器 |
| 无头浏览器 | 不支持 | 风险较高，不符合人工操作思路 |

### 11.3 启动前检查

执行商标模块前，系统检查：

- 是否能连接浏览器；
- 是否存在目标网站页面；
- 当前是否疑似登录页；
- 当前是否疑似验证码页；
- 页面是否可正常加载；
- 用户是否确认可以开始。

不满足条件时，系统暂停并提示人工处理。

## 12. 商标模块业务流程

### 12.1 输入

商标模块第一版主输入为权利人名称。

高级模式可保留“按注册号补截图”，用于复用旧 demo 能力，但不作为第一版主流程。

### 12.2 主流程

对每一个权利人执行：

```text
打开商标综合查询页
选择/定位权利人查询入口
输入权利人名称
点击查询
等待结果列表
判断是否有结果
保存目录页 PDF
从目录页识别商标记录
逐项进入详情页
保存详情页 PDF
返回目录页
继续下一项
进入下一个权利人
```

### 12.3 目录页保存

目录页是主体查询后出现的结果列表页，主要证明：

- 查询主体是谁；
- 查询条件是什么；
- 该主体名下公开显示多少条商标记录；
- 结果列表的基本信息。

即使查询无结果，也应保存无结果页面或记录无结果日志。若页面允许打印，应保存为 PDF。

### 12.4 详情页保存

详情页是从目录页中逐项点击进入的单项商标详情页面，主要证明：

- 商标名称；
- 注册号/申请号；
- 权利人；
- 分类号；
- 法律状态；
- 有效期；
- 其他公开详情。

如果同一注册号对应多个分类号，详情页命名必须包含分类号，避免互相抵充。

### 12.5 结果识别

系统应尽力从目录页识别：

| 字段 | 用途 |
|---|---|
| 注册号/申请号 | 详情页命名和日志 |
| 商标名称 | 报告展示 |
| 权利人 | 匹配校验 |
| 分类号 | 重复注册号处理 |
| 状态 | 报告展示 |

如果识别失败，仍应保存目录页，并在日志中记录“详情项识别失败，需要人工复核”。

## 13. PDF 保存规则

### 13.1 保存方式

第一版使用程序直接生成 PDF，不调用系统 `Ctrl+P` 打印弹窗。这样可以避免系统弹窗、打印机设置、保存路径对自动化流程的干扰，也能明显提高速度。PDF 的视觉要求是：页眉页脚在表面效果上尽量接近浏览器人工打印结果，让底稿查看者能够看到核查日期、网址和页码等信息。

### 13.2 页脚内容

建议页脚：

```text
核查日期：2026-07-07    网址：https://example.com    页码：1/3
```

至少应包含：

- 核查日期；
- 页面 URL；
- 页码。

### 13.3 日志补充

即使 PDF 页脚已显示日期和 URL，日志仍需记录：

- 查询时间；
- 保存时间；
- 页面 URL；
- 保存路径；
- 查询主体；
- 页类型。

## 14. 异常处理

### 14.1 异常分类

| 异常 | 处理方式 |
|---|---|
| 验证码 | 暂停，提示用户手动完成 |
| 登录失效 | 暂停，提示重新登录 |
| 页面加载失败 | 自动重试 1-2 次 |
| 查询无结果 | 保存无结果页或记录无结果 |
| 详情页打不开 | 记录异常，继续下一项 |
| 结果列表识别失败 | 保存目录页，提示人工复核 |
| 文件已存在 | 按用户设置处理 |
| 浏览器连接断开 | 暂停，提示重新连接 |

### 14.2 人工暂停机制

遇到需要人工处理的情形时，界面显示：

```text
当前任务已暂停。
原因：检测到验证码/登录失效/页面异常。
请在浏览器中完成处理，然后点击“继续”。
```

用户可选择：

- 继续；
- 跳过当前权利人；
- 重试当前步骤；
- 停止任务。

## 15. 页面加载等待策略

网页打开慢是网核自动化的重要风险。系统不能在页面刚跳转、列表还没加载出来、详情页还是空白时立即保存 PDF。

### 15.1 等待原则

每次截图前，系统都应经过“页面就绪检查”。页面就绪后才能保存 PDF。

页面就绪检查不只依赖浏览器的 `load` 事件，因为很多网站使用异步加载。应综合判断：

- URL 已进入目标网站；
- 页面主体文本长度达到最低阈值；
- 页面不包含明显的“加载中”提示；
- 页面不包含明显的错误页、登录页或验证码页；
- 查询目录页中出现结果列表、无结果提示或可识别的查询条件；
- 详情页中出现注册号、权利人、分类号、状态等至少一种关键字段；
- 页面网络空闲一小段时间；
- 页面高度和文本内容在短时间内基本稳定。

### 15.2 等待策略

默认等待策略：

```text
页面跳转后等待基础加载
→ 检查是否登录/验证码/错误页
→ 等待关键字段出现
→ 检查页面文本长度
→ 检查页面内容稳定
→ 保存 PDF
```

建议默认超时：

| 场景 | 默认等待 | 最大等待 |
|---|---:|---:|
| 打开查询页 | 5 秒 | 30 秒 |
| 查询结果目录页 | 8 秒 | 60 秒 |
| 打开详情页 | 5 秒 | 45 秒 |
| 慢速网络重试 | 10 秒 | 90 秒 |

超时后不应直接截图。系统应提示：

```text
页面疑似尚未加载完成。
你可以选择：继续等待、仍然保存、跳过当前项、手动处理后继续。
```

### 15.3 慢速网络设置

项目配置中应提供“加载等待模式”：

| 模式 | 说明 |
|---|---|
| 标准 | 默认，速度和稳定性平衡 |
| 慢速网络 | 延长等待时间，适合政府网站卡顿时使用 |
| 手动确认 | 每次保存前让用户确认页面是否加载完成 |

第一版默认使用“标准”。用户可以在运行前或运行中切换到“慢速网络”。

## 16. PDF 验证规则

PDF 验证是可选功能。它用于发现“页面还没加载出来就保存”“保存到登录页/验证码页”“PDF 内容过短或空白”等问题。

### 16.1 用户选择

项目初始化或运行前，用户可以选择：

```text
是否启用 PDF 内容验证？
```

选项：

| 选项 | 说明 |
|---|---|
| 不启用 | 默认，速度最快，适合用户手动复核 |
| 基础验证 | 提取 PDF 文本，检查关键词、文本长度和异常提示 |
| 严格验证 | 基础验证 + OCR 或截图图像检查，耗时更长 |

第一版建议实现“不启用”和“基础验证”。严格验证可预留。

### 16.2 基础验证

基础验证在 PDF 保存后执行：

- 提取 PDF 文本；
- 检查文本长度是否过短；
- 检查是否包含查询主体名称；
- 目录页检查是否包含查询关键词、结果列表或无结果提示；
- 详情页检查是否包含权利号、权利人、分类号或法律状态等关键词；
- 检查是否包含“登录”“验证码”“加载中”“403”“404”“系统繁忙”等异常关键词。

### 16.3 验证结果

验证结果写入 `capture_records.csv`：

| 字段 | 示例 |
|---|---|
| validation_enabled | true |
| validation_status | passed / warning / failed / skipped |
| validation_message | 文本过短，可能页面未加载完成 |

如果验证失败，系统不自动删除 PDF，应提示用户选择：

- 重新截图；
- 保留并标记为需人工复核；
- 跳过当前项；
- 手动处理后继续。

## 20. 核对报告

核对报告应回答：

- 本次导入了多少个权利人；
- 实际查询了多少个权利人；
- 每个权利人的每个模块是否完成；
- 每个权利人保存了多少目录页；
- 每个权利人保存了多少详情页；
- 哪些主体查询无结果；
- 哪些截图失败；
- 哪些项目需要人工复核。

### 18.1 商标专项核对

商标模块至少核对：

| 核对项 | 说明 |
|---|---|
| 每个权利人是否有目录页 | 有结果或无结果均应有记录 |
| 详情页数量是否与识别结果一致 | 能识别时核对数量 |
| 同一注册号多分类号是否分别保存 | 不能用不带分类号详情页抵充 |
| 是否存在失败详情页 | 列入缺失截图清单 |
| 是否存在需要人工复核项 | 列入人工复核清单 |

## 21. 旧 demo 迁移策略

| 旧能力 | 处理策略 | 说明 |
|---|---|---|
| 连接已登录浏览器 | 复用 | 改成配置化，不写死端口和路径 |
| 按注册号查询商标 | 保留为高级模式 | 第一版主流程改为按权利人查询 |
| PDF 保存 | 复用并统一封装 | 程序直接生成 PDF，统一页眉页脚模板 |
| 商标详情页保存 | 部分复用 | 适配权利人目录页批量详情逻辑 |
| 截图完整性审计 | 复用并项目化 | 改为读取项目日志和输出目录 |
| 删除超范围 PDF 脚本 | 不直接复用 | 必须改为 dry-run 或显式确认 |

## 22. 风险与限制

### 22.1 反爬和账号风险

工具不得绕过验证码，不得高频并发访问，不得模拟异常流量。第一版采用可见浏览器和人工接管，以降低账号风险。

### 22.2 网站结构变化

公开网站前端结构可能变化，导致选择器失效。每个模块必须单独封装，便于维护。

### 22.3 页面未加载完成风险

政府网站可能加载缓慢或异步渲染。系统必须在截图前进行页面就绪检查；如果无法确认页面已加载完成，应提示用户选择继续等待、仍然保存或人工处理。

### 22.4 PDF 验证耗时风险

PDF 文本提取或 OCR 会增加运行时间。验证功能必须由用户选择开启，默认不强制启用。
### 22.5 主体名称准确性

第一版只做格式提醒，不保证主体真实性。用户需确认输入的是准确权利人名称。

### 22.6 结果识别准确性

网站结果列表可能结构复杂。系统识别失败时应保留目录页，并提示人工复核，不得静默跳过。

### 22.7 底稿合规性

工具生成的 PDF 和日志只是辅助底稿，最终是否满足项目要求由使用者和项目组确认。
